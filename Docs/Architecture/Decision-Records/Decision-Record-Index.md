## 1. Propósito

Servir como punto único de navegación para los Architecture Decision Records (ADR) y Engineering Decision Records (EDR) aceptados, propuestos, rechazados o superseded.

## 2. Estado inicial

No existen todavía decisiones formales registradas.

Esto es intencional. La existencia de ejemplos como PostgreSQL, REST/GraphQL, Kubernetes, identidad o arquitectura de IA no constituye una decisión aprobada. Esos temas se registrarán cuando el contexto, requisitos, restricciones, alternativas, criterios, trade-offs, riesgos y evidencia permitan tomar una decisión de ingeniería defendible.

## 4. Regla de actualización

Cada nuevo ADR/EDR aceptado o modificado debe actualizar este índice dentro de la misma unidad de cambio cuando el impacto lo requiera.

Los records superseded permanecen visibles para conservar la historia de decisiones.
